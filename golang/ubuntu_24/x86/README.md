# Go для Ubuntu 24.04 x86_64

Запускать от пользователя, для которого настраивается среда. Скрипт сам вызывает
`sudo`; пароль в репозитории не хранится и из `/grok` автоматически не читается.

```bash
cd ~/serversetup/golang/ubuntu_24/x86
./run.sh --latest
./run.sh --version 1.27.3
# Допустимо также: ./run.sh 1.27.3
./run.sh --verify
```

Без аргументов устанавливается последняя стабильная версия из официального API
`https://go.dev/dl/?mode=json&include=all`. Можно выбрать существующий стабильный
релиз >= 1.21 полным номером `major.minor.patch`; preview-релизы не устанавливаются.
Выбор отсутствующей версии завершает работу до очистки текущего SDK.

## Состав

* Полный официальный SDK: `go`, `gofmt`, стандартная библиотека и её исходники,
  компилятор, линкер, ассемблер, `go tool`, `go build/run/test/vet/doc/fmt`,
  модули, workspace, race detector, coverage, fuzzing, pprof и trace.
* `gopls` — языковой сервер для редакторов.
* `dlv` — отладчик Delve.
* `goimports`, `gofumpt` — импорты и форматирование.
* `staticcheck` — статический анализ.
* `govulncheck` — проверка известных уязвимостей.
* `godoc` — классический HTTP-сервер документации.
* `pkgsite` — современный сервер документации с поддержкой модулей.
* `build-essential`, `pkg-config`, Git, curl, CA certificates, Python 3,
  tar/gzip — зависимости установки и разработки с CGO.

Инструменты собираются из актуальных модулей с проверкой Go checksum database.
Исключение — `godoc@v0.1.0-deprecated`: это официальный отдельный модуль
классического godoc. Upstream объявил его устаревшим; поэтому установлен и pkgsite.
Выбор `--version` относится к SDK; инструменты остаются актуальными. Для сборки
инструментов Go может скачать вспомогательный более новый toolchain в кэш,
но установленный `/usr/local/go` остаётся именно выбранной версией.
Точные версии и контрольные суммы собранных инструментов сохраняются в отчёте.

## Этапы и размещение

`run.sh` — точка входа, блокировка одновременного запуска и журнал. Внутренние
этапы вызываются им автоматически:

1. `10_prepare.sh` скачивает SDK, проверяет SHA256 из официального каталога,
   распаковывает в staging и собирает весь набор инструментов до замены SDK.
2. `20_install.sh` удаляет стандартные APT-пакеты SDK и snap `go`, если они есть.
   Удаление APT прерывается, если оно затрагивает сторонние зависимые приложения;
   `autoremove` не применяется. Архивный SDK заменяется целиком, без распаковки
   поверх старой версии. Старые файлы сохраняются в `/var/backups/golang-setup/`.
3. `30_configure.sh` исправляет пользовательские настройки с резервными копиями.
   Если `~/go` — обычная директория, она сохраняется вместе с проектами.
   Конфликтующий файл или symlink переносится в закрытую резервную копию.
4. `40_verify.sh` проверяет сборку и исполнение программы, modules, race tests,
   vet, CGO, форматтеры, staticcheck, govulncheck, gopls, реальный breakpoint Delve и HTTP
   документацию обоих серверов. Серверы тестов останавливаются автоматически.

SDK: `/usr/local/go`. Дополнительные инструменты: `/usr/local/libexec/golang`,
команды доступны через `/usr/local/bin`. GOPATH: `~/.local/share/go`;
результаты пользовательского `go install`: `~/.local/share/go/bin`.
`~/go` для новых кэшей и пакетов не используется.

Настройки подключаются из `~/.config/go/env.sh` в Bash и в уже существующие
профили Zsh. Сохраняются другие настройки Go, например private proxy.
Проектные `.go-version`, директивы `toolchain` и отдельные установки в asdf/mise
не удаляются. Проверка выполняется с `GOTOOLCHAIN=local`, чтобы автоматическое
скачивание toolchain не маскировало фактическую установленную версию.

После установки в уже открытом терминале:

```bash
source ~/.config/go/env.sh
hash -r
go version
godoc -http=127.0.0.1:6060
# Открыть http://127.0.0.1:6060/pkg/
# Либо в каталоге своего Go-модуля:
pkgsite -http=127.0.0.1:6061 .
```

Журналы, manifest и пользовательские копии находятся в
`~/.local/state/golang-setup/<run-id>/`; `latest` указывает на последний полностью
успешный запуск. `VERIFIED` создаётся только после прохождения всех проверок.
Кэш сборки инструментария: `~/.cache/golang-setup/` (можно удалить после установки).
В репозитории нет скачанных архивов, бинарников, паролей и машинных отчётов.

Повторный запуск разрешён: управляемые строки профилей не дублируются.
Для смены версии используется тот же `run.sh`. Резервные копии не удаляются
автоматически; восстановление системной части возможно из соответствующего
каталога `/var/backups/golang-setup/<run-id>/usr/local/`.

Изолированные регрессионные проверки конфигурации (без sudo и сети):
`./tests/test_configuration.sh`. Они проверяют повторный запуск, отсутствие
дублирования PATH, сохранение исходников и перенос конфликтующего файла/symlink.
